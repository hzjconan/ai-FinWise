## 第 1 步 · 先分清装视频的格式与压缩视频的方法

初始只读检查：仓库未发现 mp4 / mov / avi 素材；当前 PATH 没有 ffmpeg / ffprobe；backend/.venv 中 av、imageio_ffmpeg 未安装，Pillow / NumPy 已有。本轮没有安装依赖或新增实验代码，后续选择工具后逐步准备，不将工具缺失当实测结果。一次依赖搜索因 zsh 未匹配 requirements 通配符未执行，不由此推断依赖配置内容。

MP4 是容器格式，可容纳视频轨、音频轨、时间等信息；H.264 / H.265 等是视频编码方式。相同 .mp4 扩展名并不保证编码、码率、分辨率、帧率或质量相同。重新封装与重新编码是不同操作，不能通过改扩展名声称视频变小。

> 我的回答：不能；希望进一步讲解容器和编码方式的关系。

补充：原始图像帧 → 视频编码器生成压缩视频流 → 封装器将视频流、可选音频流及时间 / 索引等组织为容器文件。播放 / 训练读取时先解封装取得对应编码数据及时间信息，再解码为像素。H.264 / H.265 是编码标准，MP4 / MKV / MOV 等为容器格式；容器有支持与兼容性约束，并非任意组合都能在任意播放器运行。无声视频也可使用 MP4，音频不是必需。

容器负责轨道组织、时间戳、同步及相应索引 / 元信息，编码主要决定画面如何表示和压缩。文件总大小包括编码后各轨数据与容器开销，不能说容器完全不占空间；通常大幅体积 / 视觉质量变化须检查视频编码及参数，而非仅后缀。相同 H.264 也可因码率、质量参数、分辨率、帧率、内容等不同而大小 / 效果不同。

重新封装（remux）在目标容器支持时复制已有编码数据，通常无需解码重编码，不自动提升压缩率；重编码需解码并再次编码，可保持同编码标准而改变参数，也可换编码标准，消耗计算且有损处理可能改变质量。单纯修改文件后缀既不重封装也不重编码。当前是概念讲解，未执行视频转换。确认有无问题后继续工具准备。

### 1C：工具基础用法预习

用户要求先简单介绍工具及课程相关用法。已读取当前安装的 `-h encoder=libx264` 帮助，确认支持 preset、crf、yuv420p。此轮仅查询帮助，未生成 / 转换文件。

关系：imageio-ffmpeg 提供 Python 包和内置 FFmpeg 路径；FFmpeg 负责读取、解封装、解码、滤镜、编码及封装；libx264 是由 FFmpeg 调用的 H.264 编码器，不需要另起一个 x264 命令；MP4 不是工具，是输出容器。ffprobe 是通常单独用于结构化媒体信息探测的工具，但本环境未安装，本包不提供。

仓库根目录的 shell 用法示例（本轮仅解释，不执行转码）：

```bash
VIDEO_FFMPEG="$(backend/.venv/bin/python -c 'import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())')"
"$VIDEO_FFMPEG" -version
"$VIDEO_FFMPEG" -hide_banner -i input.mp4
"$VIDEO_FFMPEG" -i input.mp4 -c:v libx264 -crf 28 -preset medium -an output.mp4
```

变量存可执行路径，双引号避免路径分词。`-i` 指输入；单独 `-i` 可显示流信息但未指定输出会以报缺少输出 / 非零状态结束，不是文件必然损坏。`-c:v libx264` 选择视频编码器；`-crf` 质量控制参数数值越大一般损失越大、体积越小，但不保证指定码率；`-preset` 控制编码速度 / 压缩效率取舍，不是直接指定画质等级；`-an` 不输出音频，课程合成素材无音频。输出 `.mp4` 默认用于推断容器，不是编码器名。示例输入尚未生成，所以不能立即照该文件名执行。

后续 `-vf scale=320:180` 调整分辨率，`-vf fps=15` 调整输出帧率；对照每次只改变目标因素。FFmpeg 能做多种滤镜 / 编码操作，但不负责动作标签重对齐、数据集划分或模型质量验证。

### 1D / 第 2 步起点：生成并验证无损源（已实测）

为避免各压缩方案从已损失质量的视频继续转码，先固定一份 FFV1 无损编码 / MKV 容器的测试源。无损是相对 testsrc2 生成的 yuv420p 像素而言，不表示任意 RGB 转 yuv420p 都无损。MKV 不是选择无损的原因，FFV1 编码才是。

运行前已解释 `-f lavfi` 虚拟输入、testsrc2 参数、8 秒时长、ffv1 编码、yuv420p 像素格式、无音轨与 MKV 容器。仓库根目录命令：

```bash
VIDEO_FFMPEG="$(backend/.venv/bin/python -c 'import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())')"
"$VIDEO_FFMPEG" -hide_banner -nostdin -n \
  -f lavfi -i 'testsrc2=size=640x360:rate=30' \
  -t 8 -c:v ffv1 -pix_fmt yuv420p -an \
  backend/scratch/robot-video-lab/source.mkv
```

`-nostdin` 禁止交互输入，`-n` 不覆盖已存在文件，重复运行会拒绝覆盖，应先确认是否复用现有素材。新增该目录的 .gitignore 排除生成的 mkv / mp4 / png，不提交媒体产物。

### 3A：CRF 18 与 28 的文件体积（已实测）

先解释再执行命令，两份均从 source.mkv 输入，固定 libx264、medium、yuv420p、threads=1、无音轨，保留源时长 / 分辨率 / 帧率，仅改变 CRF 和输出路径。

```bash
VIDEO_FFMPEG="$(backend/.venv/bin/python -c 'import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())')"
"$VIDEO_FFMPEG" -hide_banner -loglevel error -nostdin -n \
  -i backend/scratch/robot-video-lab/source.mkv \
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -threads 1 -an \
  backend/scratch/robot-video-lab/crf18.mp4
"$VIDEO_FFMPEG" -hide_banner -loglevel error -nostdin -n \
  -i backend/scratch/robot-video-lab/source.mkv \
  -c:v libx264 -preset medium -crf 28 -pix_fmt yuv420p -threads 1 -an \
  backend/scratch/robot-video-lab/crf28.mp4
```

两条转换成功退出。逐个完整解码到 null，并核对 progress 结束、解码 frame=240、out_time_us=8000000；读取流信息确认 H.264、640×360、30 fps。

| 文件 | 精确字节数 | MB（十进制） | 平均文件速率 Mbps |
|---|---:|---:|---:|
| crf18.mp4 | 1166283 | 1.166283 | 1.166283 |
| crf28.mp4 | 423107 | 0.423107 | 0.423107 |

本例时长恰为 8 秒，因此 MB 数值与 Mbps 数值恰好相同；通常不相同。文件速率含容器开销，流信息给出的纯视频平均码率分别约 1162 与 419 kb/s。CRF 28 文件比 CRF 18 小约 63.72%，仅是该合成素材 / 固定配置结果，不是 CRF 的通用换算规律或机器人质量结论。没有对编码耗时重复计时，不能声称已测 CPU 性能提升。
