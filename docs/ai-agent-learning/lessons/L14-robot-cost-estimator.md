## 第 1 步 · 数据量

### 1A：daily_video_volume

首先只计算压缩视频每日采集字节和筛选后的上传字节，不计算带宽 / 存储 / 金额。输入为 robots、cameras_per_robot、平均 bitrate_mbps、每天 recording_hours、upload_fraction。比例是字节比例，例如 25% 写0.25，不是帧数 / 片段数比例；压缩平均码率已是每秒编码数据速率，不再额外乘分辨率与帧率。

代码核心：

```python
seconds = recording_hours * 3600
bits_per_day = robots * cameras_per_robot * bitrate_mbps * 1_000_000 * seconds
captured_gb = bits_per_day / 8 / 1_000_000_000
uploaded_gb = captured_gb * upload_fraction
```

输出 captured_gb_per_day 与 uploaded_gb_per_day，避免混淆生产量和传输量。视频已编码，不是解码像素载荷；本段忽略音轨、动作元数据、协议和重传开销。输入校验为非负整数台数、有限非负数、录制0～24小时、上传比例0～1；允许零产出 / 零上传，计算溢出则拒绝返回无穷值。

沿用 L10 示例：100台、每台2相机、平均4Mbps、每天8小时、上传字节比例0.25。讲解后已运行函数，返回每日采集2880GB、上传720GB；这是给定假设的计算结果，不是实际设备采集测量。对应18项测试通过，覆盖单位换算、默认全量上传、零产出、零上传、非法输入及计算溢出。

### 1B：required_upload_mbps

输入 `uploaded_gb` 为本次需要上传的十进制 GB，`upload_window_hours` 为允许完成上传的小时数；上传窗口与录制时长独立。函数先检查数据量非负、窗口大于零，拒绝非有限数与溢出，然后计算：

```python
total_bits = uploaded_gb * 1_000_000_000 * 8
seconds = upload_window_hours * 3600
mbps = total_bits / seconds / 1_000_000
```

讲解后实际运行：720GB 在8小时内上传需要200Mbps，在4小时内上传需要400Mbps。这里是整个窗口所需的平均有效吞吐，忽略协议、重传、网络波动；不是线路购买规格，也不表示单个机器人必须有400Mbps。聚合链路、各端可用带宽、上传时间分布仍需分别检查。本函数不估算带宽费用。

带宽补充：720GB 在2小时内传完需平均800Mbps。存储口径检查中，用户最初使用64.8TB物理占用计算按逻辑GB收费的账单，已纠正：若0.10元/逻辑GB/月已包含三副本，应按21.6TB逻辑容量计算2160元/月；用户确认无疑问。

logical_gb = daily_gb * retention_days

## 第 3 步 · 训练计算

### 3A：training_compute_cost

输入 `gpus` 为每次固定占用卡数，`hours_per_run` 为每次GPU占用小时，`runs_per_month` 为每月整数运行次数，`price_per_gpu_hour` 为每GPU小时单价。教学假设不代表真实报价；私有云按内部折算单价估出的资源成本不一定是可直接节省的现金支出。无GPU分配的排队时间不放入本例占用时长；不按GPU利用率给占用时间打折。

```python
gpu_hours_per_run = gpus * hours_per_run
monthly_gpu_hours = gpu_hours_per_run * runs_per_month
monthly_cost = monthly_gpu_hours * price_per_gpu_hour
```

先讲解函数后执行：8卡、每次6小时、每月30次、5元/GPU小时，返回每次48GPU小时、每月1440GPU小时、7200元。经过时间6小时与资源用量48GPU小时分别表达时效和资源消耗。函数只覆盖固定卡数、相同运行时长的任务；未加入checkpoint重算/保存开销，不输出CPU、存储和网络等整个平台账单。

新增15项测试覆盖GPU小时单位、扩卡缩时但费用可能增加、零训练与非法输入；成本模块累计60项测试通过。当前待本函数理解检查与疑问确认，暂不进入checkpoint成本。

### 3B：checkpoint 额外成本的输入口径

在编写下一函数前，先区分正常训练GPU时间与因中断重复执行的GPU时间。本段假设3A的1440GPU小时是未计入重算的正常训练用量；如果输入来自已经包含重算的实际GPU占用统计，则不能再次叠加相同重算时间。

重算GPU小时=重复训练时的占用卡数×每次重复训练小时×中断次数。不要用“损失进度的分钟数”直接冒充GPU分钟，也不能将Kueue排队等待时间直接算成GPU占用；恢复加载与保存时实际占用GPU的时间，后续需单独明确归属，避免漏算或重复。

理解检查采用教学假设：8卡同步训练、每月中断6次、每次从checkpoint恢复后需要重复计算10分钟、单价5元/GPU小时。这里只计算重复训练，不包含保存/加载耗时及checkpoint存储请求费。询问额外GPU小时与额外费用，待用户回答；未进入下一函数实现。

用户算出480并标为GPU小时、2400元；已纠正单位：10×6×8=480GPU分钟，除以60后为8GPU小时，费用40元。用户确认无疑问。

### 3C：checkpoint_overhead

输入均为月度汇总：`recompute_gpu_hours` 重算GPU小时、`save_load_gpu_hours` 保存/加载额外占用GPU小时、`price_per_gpu_hour` 每GPU小时单价、`storage_io_monthly_cost` checkpoint存储及读写月费。时间不再乘卡数或中断次数，已是金额的存储读写费不乘GPU单价。保存/加载GPU时间仅计本模型归于额外开销且确实占用GPU的部分；输入不应与正常训练或已有存储账单重复。

```python
extra_gpu_hours = recompute_gpu_hours + save_load_gpu_hours
extra_compute_cost = extra_gpu_hours * price_per_gpu_hour
monthly_cost = extra_compute_cost + storage_io_monthly_cost
```

先讲解后运行：重算8GPU小时、额外保存加载2GPU小时、单价5元/GPU小时、存储读写30元/月，返回extra_gpu_hours=10、extra_compute_cost=50、monthly_cost=80。2GPU小时和30元是本段新增教学假设，并非上道重算题的推导结果。本函数不模拟故障或自动选择保存间隔，不预测重算时间，也不包含其他CPU/网络等未输入费用。

新增21项测试，覆盖各费用分项、分钟换算、仅存储费、更频繁保存可能增加总费、非法输入和溢出。成本模块累计81项测试通过。待本函数理解检查与疑问确认后再进入下一步。

### 4B：compare_costs

函数输入原方案同范围月费 `baseline_monthly_cost`、新方案同范围月费 `candidate_monthly_cost` 和一次性改造投入 `upfront_cost`（默认0）。一次性投入不重复计入月费。输出 `monthly_savings` 为原月费减新月费；只有净节省为正时，`payback_months` 才为一次性投入除以每月净节省，否则为 `None`，意为无法靠月度成本节省回本，不输出负回本月数。

```python
monthly_savings = baseline_monthly_cost - candidate_monthly_cost
payback_months = upfront_cost / monthly_savings if monthly_savings > 0 else None
```

假设每月净节省不变，给出简单回本月数，可为小数；不计折现，也不自动估计质量、商业收益或作采购决定。内部折算成本的降低不一定等同可用于回收投入的现金节省，需明确所选口径。月节省为正且投入为0时回本时间为0；月节省非正时，无论投入是否为0，都返回None。
